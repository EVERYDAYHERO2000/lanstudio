# LAN Studio

React + D3, Next.js, SQLite. Схема сохраняется кнопкой «Сохранить». Координаты, устройства и связи сохраняются вместе. Начальные данные — пример, а не обнаруженные устройства. Статусы портов обозначают наличие связи в схеме, а не доступность оборудования.

## JSON

`schemaVersion: 1`, `name`, `nodes`, `links`. `revision` — версия записи базы для защиты от перезаписи из другой вкладки. При импорте используется текущая версия базы.

Узел: `id`, `name`, `type` (provider/router/switch/modem/device/container), `model`, `ip`, `mac`, `description`, `ports` (уникальные имена), `portRoles` (словарь имя порта → `wan`/`lan` для роутера), `x`, `y`, `stp`, `wifiMode` (главный роутер или ретранслятор).
Связь: `id`, `source`, `target` (ID узлов), `sourcePort`, `targetPort`, `kind` (ethernet/wireless/usb/virtual/vpn), `vlan`, `comment` (необязательный комментарий связи).

Соединение: перетащите коннектор между портами двух разных устройств. Для переноса конца существующей связи выберите линию и перетащите её выделенный конец на другой порт. Пустое место и Esc отменяют перенос. Выберите линию для изменения её параметров. Для параллельных каналов можно добавить несколько связей. Порт с соединением нельзя удалить, пока связь не удалена. Переименование порта обновляет связи.

Для анализа петель экспортируйте JSON. Поля STP и VLAN заполняются вручную. Для точного анализа L2 дополнительно понадобятся bridge/bonding, tagged/untagged VLAN, роль Mesh-каналов и реальное состояние STP — эти настройки можно пока внести в описание. Редактор не опрашивает устройства и не применяет настройки.

## Разработка

`npm run dev` — разработка. `npm run build` — сборка. `npm start` — запуск. База автоматически создаётся в `data/lan-studio.sqlite`. Развёртывание через Docker Compose описано в README.md.

У роутера WAN-порты располагаются слева, LAN — справа. Роль меняется в списке портов инспектора. В старых схемах без portRoles первый порт считается WAN, остальные LAN. Новые порты по умолчанию LAN.

Отдельный тип mesh и переключатель Mesh больше не используются. Старые mesh-узлы поддерживаются при импорте. Роль задаётся только полем wifiMode; старое поле meshEnabled принимается для совместимости и не определяет роль устройства.

Для узлов type: device поле deviceType задаёт вид устройства: other, computer, laptop, camera, nvr, microcontroller, smart-home, server, printer, tv, phone, sensor. Если поле отсутствует, используется other. Иконка зависит от этого поля.

Роутер может иметь дополнительные входы USB и модема. portTypes — словарь имя порта → ethernet/usb/modem/virtual/vpn; usb и modem у роутера всегда слева. Выключение входа удаляет его и связанные линии с возможностью отмены. Узел type: modem имеет входы провайдеров слева (portRoles: wan), выходы справа (portRoles: lan). У роутера portTypes: modem означает встроенный сотовый модем, а usb — подключение внешнего USB-модема.

У роутеров portSides задаёт положение LAN-портов: имя порта → left/right. По умолчанию LAN справа; WAN и встроенные входы всегда слева независимо от portSides.

У серверов/NAS виртуальные порты задаются portTypes: virtual и отображаются справа. Узел type: container — отдельное виртуальное устройство со стандартными полями и портами. Связь kind: virtual описывает виртуальное подключение. Это схема, контейнеры на сервере не создаются.

Установка хранит одну активную сеть. `/api/topology` читает и сохраняет её с оптимистической проверкой `revision`. `/api/versions` возвращает историю; POST с `{action:"create",label,revision}` создаёт именованный снимок, с `{action:"restore",id,revision}` восстанавливает его и автоматически сохраняет предыдущее состояние. Старые отдельные схемы при первом открытии сохраняются как версии; исходные записи также остаются в базе. Старый `/api/schemes` возвращает 410. JSON-экспорт не содержит учётных данных и сессий. API требует авторизацию; `/api/health` публичен.

## Сети, DHCP и VPN

Список `networks` принадлежит схеме: `[{"id":"home","name":"Дом","cidr":"192.168.1.0/24"}]`. CIDR — канонический адрес IPv4-сети (введённый адрес хоста приводится к адресу сети). ID и CIDR уникальны.

У роутера `natEnabled: true/false` и `dhcp: {"enabled":true,"networkIds":["home"]}`. Все ID DHCP должны присутствовать в `networks`. Удаление используемой сети заблокировано; сначала снимите её выбор в DHCP. Отсутствующие опции считаются выключенными.

VPN-точка входит в `ports`, имеет `portTypes: {"vpn1":"vpn"}` и `vpnPorts: {"vpn1":{"protocol":"WireGuard","role":"client"}}`. Роль `client` располагает коннектор слева, `server` — справа независимо от LAN/WAN и `portSides`. Протоколы: WireGuard, OpenVPN, IPsec/IKEv2, L2TP/IPsec, SSTP, PPTP, Другой. VPN-связь использует `kind: "vpn"`. Переименование и удаление порта обновляет его VPN-метаданные.

У обычного устройства USB-порт задаётся через `portTypes: {"usb1":"usb"}`. В свойствах провайдера используется `providerType`: Оптика, Ethernet, LTE, 5G, DSL, Коаксиальный кабель, Спутник, Wi-Fi, Другой. Старое поле `model` сохраняется для совместимости, но не редактируется у провайдера. Эти параметры сохраняются в SQLite и JSON вместе со схемой.

## Wi-Fi-сети роутера

`wifiNetworks` — отдельный список SSID, ключи соответствуют портам: `{"wifi1":"Home Wi-Fi","wifi2":"Guest"}`. Каждый ключ входит в `ports` и имеет `portTypes: {"wifi1":"wifi","wifi2":"wifi"}`. Точки всегда справа независимо от LAN/WAN и `portSides`. При соединении с Wi-Fi-точкой автоматически выбирается `kind: "wireless"`; несколько устройств могут использовать одну точку. SSID можно менять без потери связей. Сеть удаляется после отключения её связей. Параметры хранятся в SQLite и JSON.

У коммутатора `managed: true` означает управляемое устройство, `false` — неуправляемое. Переключатель находится в свойствах коммутатора. Если поле отсутствует, переключатель выключен. Значение сохраняется в SQLite и JSON; настройки оборудования не меняются.

Неуправляемый коммутатор (`managed !== true`) не имеет адресов управления: `ip` и `mac` нормализуются в пустые строки при чтении, импорте, редактировании и сохранении. При включении «Управляемый» поля становятся доступны; выключение очищает их.

## Физические места

Список `places` хранится внутри схемы: `[{"id":"garage","name":"Гараж"}]`. У узла необязательное поле `placeId` с ID существующего места. Отсутствующее поле означает «Не указано». Все типы узлов могут иметь место. Счётчик в таблице мест вычисляется по назначениям узлов; в JSON отдельно не хранится. Название, описание и координаты (`latitude` от −90 до 90, `longitude` от −180 до 180) редактируются в правом инспекторе; места доступны в таблице и на карте Leaflet. Координаты можно задать нажатием на карту или перетаскиванием маркера. Назначенное место нельзя удалить до переноса устройств. ID не меняется при переименовании. Старые схемы без `places` поддерживаются.

У маршрутизатора необязательное строковое поле `domainName` хранит доменное имя (например, `router.example.com`, до 253 символов). Редактируется в основных свойствах и включается в JSON-экспорт.

Привязка SSID к IP-сети задаётся у роутера словарём `wifiNetworkIds`: `{"wifi1":"home"}`, где `home` — ID из `networks`. Для каждой Wi-Fi-точки выбирается одна обязательная IP-сеть. SSID остаются в `wifiNetworks` для совместимости. Раздел «Сети» содержит общий каталог SSID в свойствах выбранной IP-сети; роутеры выбирают готовые сети из каталога. Привязанную IP-сеть нельзя удалить до снятия её назначений в Wi-Fi и DHCP.

Радиопараметры каждого SSID хранятся в `wifiRadio`: `{"wifi1":{"bands":["2.4","5"],"generations":["wifi4","wifi6"]}}`. Диапазоны: `2.4`, `5`, `6` ГГц; поколения: `wifi4`, `wifi5`, `wifi6`, `wifi6e`, `wifi7`. Оба списка допускают несколько значений; отсутствие параметров означает «не указано». Изменение и выбор доступны в свойствах IP-сети.

## Каталог Wi-Fi и ретрансляторы

`wifiProfiles` — общий список сетей схемы: `[{"id":"home-wifi","ssid":"Home","networkId":"home","radio":{"bands":["2.4","5"],"generations":["wifi6"]}}]`. Сети создаются и изменяются только в инспекторе IP-сети раздела «Сети». У роутера `wifiAssignments` сопоставляет локальную точку профилю: `{"wifi1":"home-wifi"}`. Выбор нескольких профилей создаёт несколько точек справа. Поля `wifiNetworks`, `wifiNetworkIds`, `wifiRadio` формируются из каталога для визуализации и совместимости; их отдельное редактирование не меняет профиль. Старые схемы автоматически переносятся в каталог с сохранением имён портов и связей.

`wifiMode: "router"` — главный роутер (значение по умолчанию), `wifiMode: "repeater"` — ретранслятор. `wifiMasterId` указывает главный роутер ретранслятора. Ему разрешено выбирать только подмножество профилей, назначенных главному роутеру. Ссылки на себя, другие ретрансляторы и отсутствующие устройства запрещены. Нельзя удалить главный роутер или снять его сеть, пока от неё зависит ретранслятор: сначала измените зависимость или снимите назначение. Удаление сети из каталога доступно после снятия всех её назначений.

У связи необязательное поле `networkId` содержит ID IP-сети из `networks`. На линии выводятся название и CIDR сети. При создании сеть предзаполняется по Wi-Fi-профилю, LAN/DHCP, IP конечных устройств или единственной известной сети соседних связей коммутатора. При неоднозначности остаётся «Не указана». Выбор можно изменить или очистить в свойствах связи; автоматическая настройка впоследствии его не перезаписывает. IP-сеть со связями нельзя удалить до снятия назначений.

Старые Wi-Fi-профили без привязки остаются доступны в разделе «Сети» как требующие привязки; перед сохранением нужно выбрать IP-сеть. Новые профили всегда создаются внутри выбранной IP-сети.
